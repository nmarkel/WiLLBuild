## Problem

frontend files. They are siblings, not a chain — neither contains the other's work.

The root cause of the divergence: `phase-0.10` was never merged to `Dev`, so Tyler branched
from a `Dev` that lacked it.

## Naming

The combined branch is **`phase-0.10.5`** — "0.10 plus Tyler's independent work", sitting
between 0.10 and 0.11 in the established `0.N` sequence. `phase-1.0-concierge-config` skipped
a full major version; nothing in the project is at 1.0.

`Phase 0.11 — Per-Component Finish, Taxonomy & Viewer Polish` already exists in the vault
(dated 2026-08-04) and is **unclaimed**. Tyler's branch was his own initiative, not an
implementation of that spec; the two overlap because Tyler was the source of the Round 5
feedback the spec was written from. Naming this branch `0.11` would wrongly mark that spec
delivered, so 0.10.5 keeps 0.11 live.

The rename is total: branch name, ~40 in-code `Phase 1.0` / `Phase 1.1` comment references →
`Phase 0.10.5`, plus `CLAUDE.md`, `ASSETS.md`, and docs. Tyler's 20 individual commit messages
are **not** rewritten — that would destroy authorship attribution. The rename lands as its own
commit on top, so `git log` shows the correction rather than pretending 1.0 never happened.

Both source branches stay pushed and untouched as the audit trail. Delete only after 0.10.5
merges to `Dev` and is proven.

measuring. Tyler's skip-guard preserves the manifest entry for any part whose GLB is absent,
scaling its pixel dims by the density ratio.

#### Manifest gaps this re-render closes

Audited 2026-08-06. Every gap is a real-CAD part whose GLB was absent on Tyler's machine, so
his skip-guard preserved a stale entry. **All 14 GLBs are present on this machine**, so the
re-render closes all of it:

| Part | Gap | Silent consequence today |
|---|---|---|
| `gvx-pendant`, `sh1-shepherds-hook` | 5 of 13 finishes; angles stuck on retired `az120`/`az240` set | — |
| `willstudio-side-shepherds-hook-pole-top-brackets`, `willstudio-suspension-arm-pole-top-brackets` | 10 of 13 finishes; same retired angle set | — |
| `alum-pole-12`, `bc-cl2-medium-clamshell`, `bc-round` | 5 of 13 finishes | — |
| `willstudio-cr2-decorative-crossarm` | `az315` block has **zero** finishes | Outright hole, masked by `nearestAngleKey` |

Two consequences, both currently invisible to the test suite:

1. **Per-component finish silently substitutes on the real-CAD parts.** Choosing e.g.
   `light-gray` on an SH1 arm hits `resolveRenderAsset`'s "first available finish" fallback and
   renders a different color — on exactly the parts that look best.
2. **The 8-position rotation degrades to 4.** `resolveAssemblyLayout`'s `supports45` check sees
   any part lacking `az45` and snaps the whole assembly to 90° steps. Since GVX, SH1 and both
   bracket arms are affected, this hits most WiLLstudio assemblies.

`composite.coverage.test.ts:34` deliberately exempts `REAL_RENDER_PARTS` to `CORE_FINISH_IDS`
(5 finishes) with an honest comment about GLBs living only on the owning machine — which is why
308 tests pass through all of the above. **After the re-render, delete that exemption** and
require all 13 finishes for every part, plus an exact-angle assertion so `nearestAngleKey`
fallbacks can no longer mask a hole.

Regenerate `public/renders/manifest.json` via `npm run render-manifest`, then
`node scripts/build-viewer-assets.mjs` for `viewer-assets.md`.
